## 输出变量与错误处理

创建数值变量 roll、result，文本变量 choice、error、report，以及开关 ok。每次调用可选填成功状态 ok 和错误说明 error。若 ok=false，先处理错误，不要继续使用旧结果冒充新结果。

随机数、数值列表随机与计算写数值；文字列表随机写文本；JSON和概率报告写文本。使用批量前缀时，需要预先声明全部对应类型的变量。结果、状态、错误的变量名称不得重合。返回值也可用于宿主支持的表达式/条件入口，但错误判定优先使用成功状态。

## 变量管理：临时复用与独立结果

普通、用完即弃的数值判定可共用一个数值变量，例如 `临时随机值`，另配开关 `随机成功` 和文本 `随机错误`。这里复用的是结果变量；读取变量本身不会生成新随机数。

推荐流程：**开始一次新判定 → 调用随机方法 → 检查成功状态 → 使用结果 → 结束这次判定**。

例如抽1～100后判断：≤10触发A，11～40触发B，其余触发C。三个分支都使用同一次抽取的结果，不在每次读取前重抽。下一次独立判定才覆盖临时变量。

| 场景 | 变量安排 |
|---|---|
| 立即判断、立即用完，流程不交错 | 共用一个相同类型的临时结果变量 |
| 后续对白、伤害结算或其他节点还要读取 | 使用独立结果变量，或及时复制到独立变量 |
| 批量结果要分别使用 | 声明前缀对应的多个变量；文本/数值类型匹配 |
| 嵌套调用、并行事件或会打断当前流程 | 使用独立变量，避免覆盖尚未消费的结果 |
| 首次抽取后固定 sticky | 为各事件设置独立 fixedKey；不能靠临时变量名区分事件 |

sticky 未填 fixedKey 时，记录名默认是 `value:结果变量名` 或 `batch:批量前缀`；无前缀的纯数组批量使用 `array:报告变量名`。多个事件共用结果变量且不填独立键，会复用同一条固定记录；重置时也要使用对应记录名。

失败会保留原结果，因此一定检查 successVar。成功/错误状态也会被后续调用覆盖；需要跨调用保存时，同样使用独立变量。数值临时变量不要同时承担文字或JSON报告输出。

## 随机数 rand

| 设置 | 含义 |
|---|---|
| mode | fresh 每次抽取；sticky 首次抽取后固定 |
| min / max | 有限数值，min 不得大于 max |
| digits | 0 为整数，1～6 为小数精度 |
| includeMin / includeMax | 是否允许端点，单次和批量均生效 |
| count | 1～100 整数，1 单次，2 以上批量 |
| outVar | 单次结果写入变量，可空 |
| prefix | 批量输出前缀，例如 sample_1、sample_2；填JSON报告时可省略 |
| reportVar | 完整结果数组，写JSON文本；单次如 [4]，批量如 [1,4,6] |
| fixedKey | 固定记录名称；留空使用输出变量/批量前缀派生名称 |
| fixedPolicy | fresh 忽略旧输出默认值；adopt 显式采用符合范围的完整旧结果 |

**六面骰**：fresh，min=1，max=6，digits=0，包含两端，outVar=roll。每次允许出现 1～6，连续重复是正常随机行为。

**百分位格点**：min=0，max=1，digits=2，包含两端，共 101 个可能结果，每个格点等概率。它不是连续概率密度；如果不包含两端，可得 0.01～0.99。

**批量**：预先声明 sample_1、sample_2；prefix=sample、count=2。返回值为写入数量 2；实际随机值分别写入两个变量。

**固定结果**：sticky，outVar=roll，对应默认记录 `value:roll`。默认 roll=0 仍会首次抽取。也可以提供 fixedKey=event-roll，无输出变量时仍可按此键保留返回结果。

每种精度只抽取可表示的格点。0.004～0.006 且 digits=2 没有格点，因此失败。数量、精度非法、范围反向或放大后端点绝对值超过 2^48 也会失败，不自动调整创作者配置。

## 重置 reset-fixed

key 填写要移除的固定记录名。显式命名时填原 fixedKey；默认单次填 `value:变量名`，批量填 `batch:前缀`，纯数组批量填 `array:报告变量名`。重置成功返回 true；下次调用重新抽取。结果变量保留，直到后续成功生成覆盖它。

相同键必须对应相同有效格点范围、精度和数量；配置改变先重置。固定记录随槽存档保存，不跨槽共享，也不阻止玩家读回生成前存档重抽。

## 列表抽取 rand-pick

候选表填写：

| id（宿主行 ID） | pool | label | weight |
|---|---|---|---|
| a | demo | A | 5 |
| b | demo | B | 2 |
| c | demo | C | 3 |

指定 pool=demo、field=label，结果分别有 50%／20%／30% 的概率。outVar=choice 写入内容；outIdVar 可写入宿主行 ID。短期抽取次数不保证严格符合比例。

候选范围提供三项：指定池、仅未命名池、全部池。指定池且名称为空时兼容 1.0 的全表行为；需要只取空池名时必须选择“仅未命名池”。

- 所有权重都未填写：均匀。
- 部分填写：未填写按 0，正权重按比例。
- 全部 0：默认失败；显式 uniform 策略才允许均匀回退。
- 负数、非有限数、坏表达式或缺变量：失败，不自动回退。

动态权重可写 `var("score") >= 50 ? 5 : 0`。这会读取当前 score，而不是缓存旧变量值。

### 固定概率与动态权重混用（2.1 新增）

直接在同一张表的 `weight` 列填写，不需要新增列或重建绑定：

| label | weight | 含义 |
|---|---|---|
| A | `10%` | 第一抽10%；允许重复时每抽10% |
| B | `var("b")` | 按当前 b 值分配剩余概率 |
| C | `var("c")` | 按当前 c 值分配剩余概率 |

b=20、c=30 时，A/B/C 为 **10% / 36% / 54%**；b=80、c=10 时为 **10% / 80% / 10%**。b=0、c>0 时，B 不会抽中，C 获得剩余 90%。每次调用重新读取变量。

**`10` 是相对权重，`10%` 才是固定概率。** 百分号后缀只接受数字（例如 `12.5%`），不能写 `var("b")%`，也不是表达式取模运算。这里的“固定”表示概率占比，不表示抽中结果随存档锁定；那是数值随机的 sticky 模式。

固定项可以有多行，候选也不限于三行：例如 A=`10%`、B=`20%`，C/D/E 权重为 2/3/5，则最终概率为 10%/20%/14%/21%/35%。先保留全部固定概率，再让相对权重分配剩余部分。

- 固定概率合计超过 100%：失败，不缩放固定项。
- 固定概率恰好 100%：只有固定项参与，其他候选概率为 0；仍检查所有输入是否合法。
- 未满 100% 且没有相对权重候选：失败。需要允许“无事发生”时，显式添加该候选并填写正权重。
- 剩余概率大于 0，但相对权重全部为 0：默认失败；显式选择“均匀回退”后，仅在相对权重候选中平分剩余部分，固定项保持原概率，`0%` 不会复活。
- 部分填写时，空权重仍按相对权重 0 处理；旧版纯数字/表达式规则保持。

允许重复时，概率是每次独立抽取的机会，不保证十次恰好中一次；连续出现相同结果是正常行为。不重复批量的后续条件概率会变化。整数/小数随机支持一次 1～100 个；权重文字支持一次1～100条，可选允许重复或同批不重复。

### 一次抽取多条文字（2.1 新增）

在“列表随机（安科式）”中设置：

| 参数 | 用途 |
|---|---|
| 抽取数量 count | 1～100，默认 1 |
| 重复规则 replacement | with 允许重复；without 同批不重复 |
| 结果变量 outVar | count=1 写入普通文字；count>1 写入 JSON 文本数组 |
| 行ID变量 outIdVar | 单次为普通 ID；批量为对应顺序的 ID JSON 文本数组 |
| 批量逐条输出前缀 prefix | 可空；批量时填 choice，依次写入 choice_1…choice_N |

例如 count=3、prefix=choice，先声明 choice_1、choice_2、choice_3 三个**文本变量**，即可在剧情中分别使用。outVar 可另存完整结果，例如 `["A","B","A"]`，也可留空。count=1 保持旧行为，prefix 不生效。

- **允许重复**：每抽概率相同，A 的固定 10% 在每一抽都保持 10%。数量可以超过候选行数。
- **同批不重复**：抽中后仅在本批内移除该行；下一次调用恢复完整候选池。后续按未抽中行的**初始有效概率**重新归一化，不重新预留固定百分比。例如初始 A/B/C 为10%/36%/54%，A 抽走后 B/C 为40%/60%；B 抽走后 A/C 为15.625%/84.375%。固定10%仅是第一抽概率，不是整批入选率。
- 不重复按**行**判断。两行 label 相同，仍可能各抽一次；如希望文字也不重复，应先合并重复内容。
- 原本概率为0的行不会在后续抽取中被启用；固定概率占满100%时，其余行也不会因固定项已抽走而解锁。
- 同批不重复的数量超过正概率候选数时，整批失败，不提前抽取或部分写入结果。
- 每批只读取一次候选表并计算一次动态权重，批内使用该快照；下次调用才读取更新后的变量。逐条结果在全部抽完后一起写入。
- “检查候选池与概率”展示的是本批**第一抽**的分布，不代表无放回抽取的后续条件概率或整批入选率。

批量数量改变时，仅写入本次涉及的变量；例如先抽3条再抽2条，choice_3 保留旧值，不应把它当成本次结果。配置错误保留已有输出，使用 successVar/errorVar 判断是否成功。

### 权重抽数字与数学表达式

选择 **“列表随机（数值／公式）”**（`rand-pick-number`）。候选范围、权重、固定百分比和两种重复规则与文字抽取一致；输出是可以直接参与数学运算的数值。

| label（默认输出列） | weight |
|---|---|
| `10` | `10%` |
| `2.5` | `2` |
| `var("power")*2+0.5` | `3` |

power=4 时，上表抽取的数值是10、2.5或8.5，第一抽概率为10%、36%、54%。也可以另设数值/公式列，并把“输出列 field”改成该列名；文字名称可以留在 label 中。

- **单次**：count=1，outVar 选择数值变量；方法直接返回抽中的数值。
- **批量**：count=2～100，必须填 prefix，并预先声明对应的数值变量。例如 prefix=roll、count=3，写入 roll_1、roll_2、roll_3；方法返回本次数量3。
- **完整数组**：reportVar 可选一个文本变量，写入如 `[10,2.5,8.5]` 的 JSON；其中的元素是数字，不是带引号的数字字符串。单次报告也是数组，如 `[8.5]`。
- outIdVar 可写入单条 ID 或批量 ID JSON 文本；successVar/errorVar 与原方法相同。合法结果也可能是-1，应根据成功状态判断失败。
- 数值支持整数、小数、负数、科学记数法，以及已有白名单表达式和嵌套表函数。输出结果不自动取整；需要取整时在公式中使用 floor 或 round。
- 批内权重和数值公式均按调用时的变量求值一次，然后抽取；抽取结束后写入结果。公式本身不再额外生成随机数。同批不重复按行排除，因此不同公式算出同一个数字仍可能都出现。
- 所有候选的数值公式都会在抽取前验证，包括零概率行；非法文字、缺变量、除零和非有限结果均失败并保留原输出。

若只是需要“1～100随机整数”或“0～1随机小数”，继续使用原 **随机数 rand**，无须建立候选表。若需要不同数字具有不同概率，或抽取候选公式的计算结果，使用数值列表随机。

## 跨多次调用不重复：抽取池与数组（2.2 新增）

原来的“同批不重复”只对一次调用有效。新抽取池会把剩余项保存到当前存档槽；一次抽一项、隔几个节点再抽、或分批抽取，都不会重新加入已经取出的项。

### 两种抽取方式

| 方式 | 何时随机 | 读回同一份存档后 |
|---|---|---|
| 建立时洗牌 `fixed` | 建池时生成完整顺序，此后从头取出 | 若该存档已包含建好的池，后面的顺序相同 |
| 每次随机 `remaining` | 每次仅在剩余项中抽取，取出后移除 | 可能得到不同结果，也可能碰巧相同 |

两种方式都使用随机数。第二种相当于抽前打乱剩余部分再取头部，但不必反复重排整个数组。它不是保证每次不同的“真随机”开关；插件使用 JavaScript Math.random，没有密码学随机或指定种子。

**固定顺序从建池后开始生效。** 如果读回建池之前的存档，重新建池仍会产生新顺序。已抽项目会随着读档回到那个存档时的状态；本功能不是跨存档防 SL。建立、抽取、查看和重置的执行顺序由剧本决定，菜单刷新与单纯读取变量不应调用抽取方法。

### 最小例子：三个选项各出现一次

先声明文本变量 `picked`、`bag_json`、`bag_error`，数值变量 `bag_left`，开关 `bag_ok`。

1. 在本轮开始处调用 **建立不重复抽取池**：名称 `events`，来源“JSON数组”，数组 `["调查","休息","交谈"]`，结果类型“文字”，方式“建立时洗牌”。成功状态填 `bag_ok`、错误说明填 `bag_error`。
2. 先检查 `bag_ok=true`。需要一个选项时调用 **从抽取池取出**：名称 `events`，数量1，单项结果 `picked`，结果数组 `bag_json`，剩余数量 `bag_left`，同样填写成功和错误变量。
3. 检查成功后使用 `picked`。后面的节点只重复第2步；三项各出现一次，第三次后 `bag_left=0`。
4. 抽空时走结束分支。要开始新一轮，先 **重置／删除指定抽取池** `events`，再建立一次。

不要把“建立”放在每次抽取前。同名池重复建立会报错，不会偷偷重置；重新开始本轮须显式重置。建议用剧本开关标记建池成功，或先用“查看抽取池”检查是否存在，再按成功状态分支。

### 从随机候选表建立

来源选“随机候选表”，沿用 `pickTable` 绑定、候选范围、池名、输出列和零权重策略。表中每个参与项目必须有唯一的宿主行ID。

- 不填写任何权重时均匀洗牌／抽取；填写后遵循原权重、固定百分比及错误校验规则。
- 权重为0的项目不进入新池；不会在其他项抽完后被启用。
- 数值类型支持已有白名单公式与函数表。所有数值公式先校验，包括零概率行。
- 建池时一次性读取权重和公式结果。之后改表或变量不会改变已建的池；要应用新配置，应明确重置后重新建立。
- 非均匀权重使用加权不放回顺序。固定百分比只约束第一抽；后面按剩余项的初始概率重新归一化，不是每抽都重新预留固定百分比。

例如 A=`10%`、B=`2`、C=`3`，第一抽为10%／36%／54%；A取出后，B/C变成40%／60%。固定顺序模式建池时就按这条规则生成整条顺序，每次随机模式在取出时应用它。

### 数组输入与输出

当前 SDK 的普通项目变量不支持原生数组值，因此数组使用 **JSON文本变量**；插件内部保存结构化数组，无需作者拆成几百个变量。

- 建池 `source=array`：文字数组如 `["A","B"]`，数值数组如 `[1,-2,3.5]`。数组元素必须同类型，不接受对象、嵌套数组、null或非有限数。
- `arrayVar` 可读取已有文本变量中的JSON数组；填写后优先于 `arrayJson`。输入数组只读取，不会改写原变量。
- 范围随机 `rand` 新增 `reportVar`：单次也返回形如 `[4]` 的数组报告；批量时可只填此报告变量、不填前缀，方法返回数量，数组存入文本变量。
- 数值列表随机原有 `reportVar`、文字列表随机批量 `outVar`，都可作为新池的数组输入。数组输入按各元素等权处理，不携带原表权重；要保留权重请直接从候选表建池。
- `deck-draw` 的返回值始终是JSON数组文本，例如 `["A"]` 或 `[1,2]`；`outVar` 只在数量1时写入实际文字或数值。
- 批量可只接收JSON，也可填 `prefix` 写入预先声明的同类型变量。仅写本次数量涉及的变量；多余旧变量不清空。

### 相同内容怎么处理

默认 `uniqueBy=value` 合并相同结果，合并项权重相加、行ID使用第一项ID。数值公式按求值结果比较，文字精确比较并区分大小写，不自动删空格。这适用于“某个选项出现过就不再出现”。

选择 `uniqueBy=row` 时按行／数组位置区分，内容相同的两项仍能各出现一次。数组行ID为 `array:1`、`array:2` 等，表来源保留宿主行ID。

### 方法与参数

| 方法ID | 主要参数 | 返回与作用 |
|---|---|---|
| `deck-create` | `key`；`source=table/array`；表参数或 `arrayJson/arrayVar`；`valueType=text/number`；`mode=fixed/remaining`；`uniqueBy=value/row`；`outVar` | 返回建池后的项目数，失败-1；outVar可写完整池报告 |
| `deck-draw` | `key`；`count=1..100`；`outVar`；`prefix`；`reportVar`；`outIdVar`；`remainingVar` | 返回本次JSON结果数组，失败空串；移除取出的项 |
| `deck-peek` | `key`；`outVar`；`arrayVar`；`remainingVar` | 返回池报告；arrayVar只写剩余结果数组；不抽取、不洗牌 |
| `deck-reset` | `key` | 删除指定池，返回是否成功；不清空旧输出，不自动再建立 |

四个方法都可填写 `successVar` 与 `errorVar`。`deck-draw.outIdVar` 始终写ID数组JSON，单次也一样。池报告包含 `key/mode/valueType/total/drawn/remaining/values/ids`；fixed 的 values 是后续取出顺序，remaining 的 values 是剩余集合排列，不是未来随机结果。

### 存档、失败与限制

- 新字段 `drawDecks` 按槽存档保存，与旧 `fixedResults` 分开；不跨槽共享。旧存档没有新字段时视为空池，不覆盖旧固定随机记录。
- 单池最多10000项，同槽最多100个池；所有池剩余项合计最多20000，序列化记录合计最多4000000字符。数组输入最多1000000字符，名称1～128字符。用完的空池仍占一个池名，可显式删除。
- 本次数量超过剩余量时整批失败，不抽取、不部分写出、不自动循环补满。请先检查余量，再决定结束或开始新一轮。
- 参数、类型、候选和输出重名错误会保留池与原结果。宿主写入异常时尝试回滚池和已写变量；宿主反复拒绝恢复写入时无法承诺数据库式事务。
- 同一扩展实例的池操作拒绝并发重入。异步建池被宿主取消或期间存档状态发生变化时拒绝提交。失败时检查状态，不消费旧结果。
- 回退旧插件版本时，新池方法与存档字段不能被旧版理解；先保留升级前的工程和存档副本。


## 概率检查 preview-pool

该方法检查候选与权重分布，不计算数值输出列中的公式，也不检查批量数量是否足够；数值公式和批量约束由对应抽取方法在抽取前检查。

参数与列表抽取的候选范围、池名、输出列、剩余概率全零策略一致；outVar 可写入 report。检查不会抽取或推进随机序列，结果为 JSON 文本：

```json
{
  "scope": "named",
  "pool": "demo",
  "unweighted": false,
  "fallback": false,
  "fixedProbability": 0,
  "remainingProbability": 1,
  "candidates": [
    {"id":"a","value":"A","kind":"relative","weight":5,"probability":0.5},
    {"id":"b","value":"B","kind":"relative","weight":2,"probability":0.2},
    {"id":"c","value":"C","kind":"relative","weight":3,"probability":0.3}
  ]
}
```

probability 是 0～1 的小数，乘 100 得百分比。fixedProbability 是固定项预留的总概率，remainingProbability 是相对权重可以分配的剩余概率。kind 为 fixed 时，weight 表示所填百分数（如 10），probability 为 0.1；kind 为 relative 时，weight 是本次求值的相对权重。fallback 表示是否对相对权重使用均匀回退；回退的相对权重报告为 1，固定项保持原值。

纯相对权重的旧字段含义保持，2.1 只新增报告字段；读取报告时应允许额外字段。固定混合示例的报告关键部分：

```json
{
  "fixedProbability": 0.1,
  "remainingProbability": 0.9,
  "candidates": [
    {"id":"a","value":"A","kind":"fixed","weight":10,"probability":0.1},
    {"id":"b","value":"B","kind":"relative","weight":20,"probability":0.36},
    {"id":"c","value":"C","kind":"relative","weight":30,"probability":0.54}
  ]
}
```

JSON 中的小数可能带有浮点尾数（例如 0.36000000000000004），显示时可按需要取小数位。

## 计算 calc

基础运算：add、sub、mul、div、pow、root、floor、round。输入 a/b；root、floor、round 只使用 a。除零、负数开平方以及非有限结果会失败。

选择 func 后填写 funcName 与 x/y/z/w。例如函数规则表：

| name | expr |
|---|---|
| double | x*2 |
| nested | double(x)+1 |
| bounded | clamp(round(x*y),0,100) |

nested 输入 x=3 得 7；bounded 输入 x=60、y=0.5 得 30。嵌套函数省略参数按 0，最多 4 个参数。函数只能计算，不写变量、不执行任意脚本。

## 表达式

支持 +、-、*、/、^、括号、比较和三元条件，以及 sqrt、pow、floor、round、min、max、clamp、var。一元 +/-、科学记数法可用；`var("score")` 读变量。数值文本可转为数字；开关 true/false 转成 1/0；缺变量、空文本或非数值内容报错。

幂高于乘除并右结合：`2*3^2=18`、`2^3^2=512`、`-2^2=-4`、`(-2)^2=4`、`2^-2=0.25`。比较返回 1/0，三元只求值所选分支。比较按左结合处理，不支持数学式链式区间语义。

不支持 &&、||、赋值、分号、任意 JavaScript 或自由字符串运算。字符串仅用于 var 参数。round 遵循 Math.round：`round(-1.5)=-1`。

上限：候选 10000 行、函数规则 1000 行、表达式 4096 字符、约 1024 个语法单元、解析深度 32、函数调用深度 32、每次表达式求值最多 4096 次函数调用、固定记录 10000 条。函数库会整体检查重名、保留名、缺依赖和循环引用。

## 验收建议

检查结果类型、批量全部输出、错误分支、固定结果跨节点复用、保存后读档、生成前读档、改变配置后重置以及实际导出平台。读档恢复期间不会重新建池、抽取、重置或覆写输出；玩家继续推进或快进时正常执行。Studio明确标记的编辑器定位仍会重建状态，因此验证存档请使用真正的保存／读取功能。无法识别定位目的的宿主在立即回放时保留已有状态，建议从章节入口完整运行。宿主写入故障不属于可保证的跨变量原子事务。

## 从1.0升级的必要检查

升级前保留工程与旧存档副本。固定结果改为独立槽记录；若要继承已经生成的旧结果，显式选择 fixedPolicy=adopt，不要把默认0误认为旧随机结果。批量数量只接受1～100整数，必须声明全部前缀变量；全零权重默认失败，只有有意均匀回退时才选择 emptyPolicy=uniform。缺变量、非法公式和负权重均报错。幂高于乘除并右结合，旧公式若依赖原顺序请加括号：旧意图 (2*3)^2=36、(2^3)^2=64。改变固定记录的范围、精度或数量后先重置对应记录。每次调用先检查成功状态；回退1.0时恢复升级前副本。2.0／2.1升级2.2无需改表结构或旧方法ID。
