# 从 1.0.0 升级到 2.0.0

先备份使用中的扩展、项目与存档，再在副本中升级。请勿直接用新版覆盖唯一的旧版副本。

## 为什么是 2.0.0

这次不仅新增方法，还改变了此前公开行为：固定结果的判定方式、全零权重、非法数量、幂运算顺序和错误处理。按照[语义化版本规范](https://semver.org/lang/zh-CN/)，这些不兼容变化使用新的主版本号。旧版 v1.0.0 保持原样。

## 逐项迁移

| 1.0.0 行为 | 2.0.0 行为 | 接入方式 |
|---|---|---|
| sticky 直接复用非 undefined 的输出，默认 0 也算已生成 | 插件槽存档独立记录首次生成 | 新流程使用默认策略；继承旧结果时显式选 `fixedPolicy=adopt` |
| 批量 sticky 只检查第一项 | 校验并保存整个批次 | 预先声明全部 `前缀_1..N` 数值变量 |
| 批量忽略包含端点开关 | 与单次完全一致 | 检查过去未生效的开关设置 |
| count 大于 100 被截成 100 | count 必须是 1～100 的整数，否则失败 | 修改越界或非整数配置 |
| 无正权重时可能自动均匀抽取 | 全零默认失败；非法/负权重报错 | 只有确实需要全零均匀抽取时，选择 `emptyPolicy=uniform` |
| 缺变量可能按 0 计算 | 缺失或不可转为有限数值时报错 | 声明并初始化表达式引用的变量 |
| `^` 与乘除同级、左结合 | 幂优先且右结合 | 为依赖旧顺序的表达式增加括号 |
| 改变随机配置仍可能复用原值 | 固定记录配置不符时报错 | 先调用 `reset-fixed` 再重新生成 |

## 固定结果示例

新流程：声明数值变量 `roll`（默认 0），调用 rand，设置模式 sticky、范围 1～6、outVar=roll。首次生成后，同一存档中的 `value:roll` 记录会被复用。

继承旧存档：选择“采用完整的既有结果”。如果 roll=4，且当前范围/精度允许 4，就把它接入固定记录；无效结果不会被静默接受。此策略无法替你判断某个合法范围内的旧默认值是否曾真正抽取过，应根据旧流程决定。

命名记录：两个节点设置相同 `fixedKey=event-roll`、相同范围/精度/数量，即可共享结果，不要求写入同一个变量。重置时填 `event-roll`。未填写 fixedKey 时，单次默认键为 `value:变量名`，批量默认键为 `batch:前缀`。

固定记录跟随槽存档；读回生成前的存档可以重抽。2.0.0 不提供跨存档防 SL 或指定种子的随机序列。

## 公式迁移示例

- 旧表达式 `2*3^2` 如有意表示先乘后求幂，请改为 `(2*3)^2`，结果 36。
- 旧表达式 `2^3^2` 如有意表示左结合，请改为 `(2^3)^2`，结果 64。
- 新版默认 `2*3^2=18`、`2^3^2=512`、`-2^2=-4`。
- 不要用链式比较表达数学区间；写 `x>=1 ? (x<=6 ? 1 : 0) : 0`。

## 错误分支

为方法配置一个开关 `ok` 和文本 `error`。调用后先判断 ok，再使用结果；失败时读取 error。随机/计算失败返回 -1，但合法结果也可能为 -1；列表失败返回空串，也可能与合法空内容重叠。

结果、状态、错误不能指向同一变量。批量输出需要全部声明；状态写入不能替代宿主数据库事务。如果宿主本身写入失败，只能尝试恢复既有结果。

## 数据与版本字段

扩展版本升级到 2.0.0；pickTable / funcLib 的列结构和契约没有变化，所以数据契约版本保留 1.0.0。SDK 最低声明保持原值，实际集成验证宿主为 Studio 1.21.0；这两个版本与扩展版本分别表示不同内容。

回退到 1.0.0 时应恢复升级前的项目/存档副本；不要假定旧版能理解新版固定记录或新方法。
